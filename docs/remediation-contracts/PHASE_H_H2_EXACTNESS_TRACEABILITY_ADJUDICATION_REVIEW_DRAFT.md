## 2. H2 counting rule

H2 counts missing **historical propositions**, not every bullet or sentence.

Within one node, audit labels, migration ordinals, fixture labels/order, closure-list form, amendment wording, and worked examples may be grouped into one **historical-form provenance packet** when:

1. they share the same recovery source packet;
2. they have the same practical treatment;
3. recovering the node's original confirmation exchange would answer them together; and
4. separating them would create bookkeeping inflation without changing authority or remediation treatment.

Do not group distinct representation questions merely because the same source packet might mention both. For example, an exact Boundary Decision schema and an exact three-phase literal string set are separate propositions because one can be recovered/adopted independently of the other and they serve different implementation surfaces.

The H1 consequence discriminator also applies: exactness debt must not be described as safety-blocking when the semantic invariant is already complete.

## 3. R1–R3 assurance-status treatment

R1–R3 still do not receive primary H2 exactness entries merely because their current artifacts carry fidelity-review checklists. A checklist saying exact labels/fixtures/fields must be reverified is a process obligation, not proof that a specific historical proposition is unavailable.

H3 must reconcile their actual named source basis before any primary source-exhaustion entry is created.
