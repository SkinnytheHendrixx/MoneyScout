## 1. Purpose

This artifact reconciles the complete nine-item Phase-I naming/class/string handoff into the remediation DAG.

It does not re-derive Phase-H source-gap boundaries and does not manufacture new historical exactness claims.

The governing rule is:

> Phase I owns only the unresolved naming/class/string choice that must be adopted for the corrected present-day authority corpus. It does not own semantic meaning, storage identity, equality, cardinality, lookup behavior, or historical wording unless those are independently recovered from stronger source evidence.

Where a Phase-H row combines naming with representation, this reconciliation splits the responsibilities explicitly:

- `NAME-*` owns the adopted present-day label/name/literal;
- the applicable semantic or representation node owns behavior, persisted identity, equality, cardinality, and reference mechanics;
- historical exactness remains source/traceability debt unless recovered.

No Phase-I naming resolution may be represented as proof of the historical original name.

## 3. NAME-node ownership rules

Every Phase-I row receives one `NAME-*` remediation owner.

### 3.1 NAME nodes may do

A NAME node may:

- recover the historical name from a stronger source and adopt it if verified;
- adopt a governed present-day replacement when historical exactness remains unavailable;
- define canonical spelling, casing, literal values, or public/internal labels for the corrected authority corpus;
- define migration aliases only where they do not alter semantic meaning or identity.

### 3.2 NAME nodes may not do

A NAME node may not:

- redefine the underlying semantic category;
- choose a name that silently merges or splits semantic states/classes;
- alter equality or uniqueness rules;
- become the persisted identity owner where identity is separately governed;
- close a representation finding merely because a label was selected;
- claim historical provenance that source recovery did not establish;
- bypass the consuming node's PRE/POST BCT if the adopted name is embedded in code/schema/configuration.

### 3.3 Pull-forward test

If selecting a purported name would change:

- equality;
- uniqueness;
- lookup;
- cardinality;
- lineage;
- policy matching;
- registry membership;
- migration interpretation;
- fixture outcome;

then that portion is not pure Phase-I naming work. It must be attached to the semantic/representation DAG node that owns the behavior, while the NAME node retains only the literal label choice.

## 6. Historical-name non-laundering rule

Each Phase-I resolution must carry one provenance state:

- `HISTORICAL_NAME_VERIFIED`
- `GOVERNED_PRESENT_DAY_ADOPTION`

No third ambiguous state is permitted.

If source recovery proves the original historical name, preserve the source and immutable evidence reference.

If historical exactness remains unresolved, the corrected register must say explicitly that the adopted term is a **current governed name**, not recovered historical truth.

A later source recovery that conflicts with an adopted current name does not retroactively make the current adoption invalid. It triggers a governance decision about whether to migrate names, preserve aliases, or retain the adopted current term, with historical provenance corrected separately.

## 7. Naming migration rule

Where a chosen Phase-I name is persisted in schema/config/code:

1. inventory every existing/current literal and consumer;
2. distinguish display alias from semantic identifier;
3. preserve historical rows/events without reinterpretation;
4. migrate only under explicit mapping from old current implementation literal to new governed literal;
5. do not mutate historical event meaning merely to normalize spelling;
6. if a literal participates in equality/policy lookup, the representation owner must approve and recheck the migration;
7. PAIM-B/C must invalidate consumers that relied on the changed literal as implementation evidence.
