## 1. Purpose

This artifact integrates the reviewed C/F/G/H/I/J remediation obligations into one typed dependency DAG.

It is not a stitched summary and it does not authorize implementation. Its purpose is to prove that previously separate phase reconciliations compose without:

- duplicate normative ownership;
- missing cross-phase prerequisites;
- contradictory closure gates;
- stale-evidence races;
- source-gap laundering;
- mechanical-name changes bypassing representation/governance review;
- provider-path blockers becoming global blockers;
- shared physical roots being consumed during unstable amendment intervals;
- Phase-J governance freezing around unsettled authority semantics.

The integrated register preserves each phase's own denominator and object type. It does **not** create one naive global finding count, because some later-phase rows are intentionally views or carry-forwards of earlier rows rather than independent findings. Phase-I's nine NAME rows, for example, are the naming carry-forward of nine Phase-H rows, not nine additional source gaps.

## 3. Object-type discipline

The register contains distinct object types that must never be collapsed merely because one physical change affects several of them.

### 3.1 `FINDING`

A current normative noncompliance or unresolved governance/representation condition.

Examples: F06-01, G2-01, J-F04.

### 3.2 `SOURCE_GAP`

A missing historical/source proposition whose authority consequence may be BLOCK-PROVIDER, SAFE-CONSERVATIVE, SAFE-FALLBACK, or EXACTNESS-ONLY.

Examples: H1-S07, H2-E39.

### 3.3 `NAME_CARRY_FORWARD`

A Phase-I present-day naming decision attached to an underlying Phase-H row. It does not increase the Phase-H denominator and cannot close the source-gap row by itself.

### 3.4 `SEMANTIC_RULE_NODE`

A remediation node that defines a missing cross-node rule.

Examples: RD-C-R17-R18, RD-C-R5-R20.

### 3.5 `UNRESOLVED_TRANSITION_NODE`

A seam whose owners already compose but admit multiple materially distinct coherent transition readings.

Example: RD-C-R11-R8 / C21-03.

### 3.6 `REPRESENTATION_NODE`

A node that creates or repairs exact/arbitrary-N identity, cardinality, reference, set-membership, or lifecycle representation.

### 3.7 `RETENTION_NODE`

A node-specific historical-addressability closure prerequisite.

### 3.8 `GOVERNANCE_NODE`

A Phase-J future-code governance obligation.

### 3.9 `CERTIFICATION`

A pinned audit conclusion with its own lifecycle and invalidation reason. Certifications are not findings.

### 3.10 `ATTACK`

An adversarial fixture/escape case. An attack may close or reopen without becoming another finding.

## 12. Cross-phase interaction findings surfaced by integration

### XPI-01 — R20 Boundary Registry is a four-layer dependency chain, not one remediation checkbox

**Severity:** HIGH

The integrated register reveals four distinct obligations that all touch what a casual implementation plan might call “the Boundary Registry”:

1. **F02-02 / REP-F02-02** — does a canonical/equivalent registry representation exist and is it representable/addressable?
2. **H2-E39** — what is the exact historical/current registry representation/form? Historical exactness may remain unresolved even after a current governed representation is adopted.
3. **NAME-H2-E41** — what boundary-class literals are adopted, and are they mechanical registry keys/policy selectors?
4. **J-F02 / GOV-J-F02** — are consequential surfaces actually required to register/re-register against the registry before merge/release?

These are not duplicates.

#### Required ordering

At minimum:

`R20 boundary semantics stable`
→ `REP-F02-02 current governed registry representation resolved`
→ `H2-E39 exactness disposition attached without historical laundering`
→ `NAME-H2-E41 mechanical key adoption + REP/GOV joint sign-off`
→ `GOV-J-F02 mandatory registration enforcement`

The exactness and NAME work may be designed in parallel where safe, but neither may falsely close F02-02 or J-F02.

#### Closure prohibition

No node may state “Boundary Registry fixed” unless its own layer-specific predicate is named.

A registry schema existing does not prove registration enforcement.
A historical representation name being unrecovered does not prevent a governed current registry from existing.
A boundary-class label being selected does not prove the registry key is correctly wired.
J-F02 enforcement cannot close against a registry representation whose key semantics remain unstable.

## 16. Certification invalidation semantics

Finding state and certification state remain separate.

### Finding lifecycle

`OPEN → AMENDED_PENDING_RECHECK → CLOSED`

or `REMEDIATION_INCOMPLETE`.

### Certification lifecycle

`CURRENT_CERTIFIED → INVALIDATED_BY_CHANGE[type] → RECHECK_PENDING → RECERTIFIED_CURRENT`

The old certification remains historically valid for its pinned evidence where applicable.

Invalidation type determines recheck depth:

- semantic target changed → full re-adjudication;
- implementation evidence changed under stable semantics → evidence re-execution;
- shared root changed → every evidence consumer discovered by PAIM-C is invalidated;
- mechanical literal changed → representation/configuration consumers and migration fixtures are invalidated;
- source recovery changes a previously governed/current assumption → affected downstream semantics/exactness/naming conclusions are invalidated, not silently rewritten.
